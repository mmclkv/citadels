# 不完全信息搜索：按玩家可见历史共享决策

## 修复的问题

物理搜索树中的分支可能来自其他玩家的私有观察。过去的 MCTS 仅在同一个父节点下按下一行动者的信息集哈希查找子节点，因此同一玩家后来再次行动时，无法区分的两个隐藏世界仍可能保有不同的动作统计，形成不可执行的知情策略。

最小反例：秘密变量为等概率的 0/1，对手知道秘密但只能做同一个不透露秘密的动作，之后由根玩家猜秘密。合法策略的期望收益最多 0.5；旧顺序及批量 MCTS 在 20000 次模拟后估计约 0.995。如果另有收益 0.75 的安全行动，旧搜索仍把约 98.6% 的访问分给实际期望只有 0.5 的冒险行动。

## 实现

- `SearchInformationHistory` 为每个模拟世界维护各玩家独立的观察历史。初始化只包含该玩家当前可见的状态；搜索中仅在观察发生变化、做出自己的选择或观察到公开行动时扩展历史。
- `GameAdapter::observation_hashes` 投影所有玩家的当前观察；`visible_action_hash` 表示行动额外公开的证据。默认适配器沿用既有信息集键，原生游戏使用 `search_observation.hpp` 的显式投影，共享公共部分计算。
- 对手私有手牌、未公开角色、真标记、隐藏声明顺序、牌堆顺序和 RNG 不进入其他玩家的观察。法师依法看到的手牌、灯塔查看牌堆等私有信息只加入有权观察者的历史。
- 物理树节点仍保存各模拟路径；独立的 `InformationSetStatistics` 按行动者自己的观察历史共享动作访问次数、累计收益及批量搜索预留次数。PUCT 的 Q、FPU 和 U 都使用这份共享统计。
- 多人终局与叶节点收益按行动者视角旋转回传。根访问分布也由共享动作统计生成，避免输出重新依赖物理分支。
- 顺序和批量 MCTS 使用相同语义。保留的启发式子树通过 `shared_ptr` 持有统计，继续依照实际可见信息进行保守失效与推进；树拓扑不形成所有权循环。
- 新观察只会影响有权知道它的玩家。已经观察过的信息即使从当前画面消失，也保留在该玩家的模拟历史中。

策略和动作编码、网络架构、参数数量、终局收益定义和实战按访问分布抽样的方式均不变，因此现有策略权重可以直接使用。下一次正常启动时，原生构建器会识别头文件变化并重新编译。

## 回归验证

`native/information_set_regression.cpp` 验证顺序搜索和 batch=1/8/32/128 的批量搜索：

1. 不可观察的等概率秘密，收益估计接近 0.5。
2. 隐藏世界权重 4:1，选择多数猜测，收益估计接近 0.8。
3. 安全选项收益 0.75，应获得超过 95% 的根访问。
4. 合法观察到秘密后，允许不同决策，收益可接近 1。
5. 中途看到秘密、决策时已不再显示，仍须记住信息，不能按当前快照错误合并。
6. 原生观察的隐藏手牌、角色、真标记、私有声明顺序与 RNG 非干扰性，以及法师和真标记拥有者的私有可见性。

编译器可用时运行：

```sh
python -m unittest python_backend.test_information_sets python_backend.test_batched_mcts python_backend.test_mcts_cycles python_backend.test_mcts python_backend.test_neural_selection
```

设置 `CITADELS_TEST_GAME_ENGINE` 为新编译的规则引擎后，还可运行 `python_backend.test_native_heuristic_search`，覆盖真实行动、训练推进和树复用。

## 修复范围

本次信息集修复保留搜索模拟过程中已经获得的信息，不新增真实对局完整历史后验滤波，不改变对手行为模型，也不将网络改为历史输入架构。后续已独立实现[搜索中逐步补充根隐藏世界](progressive-root-worlds.md)，下方对照仍是启用该后续功能前的结果。网络曾学习旧搜索目标的偏差也不会自动消失，应先冻结权重评测，再决定是否续训。
