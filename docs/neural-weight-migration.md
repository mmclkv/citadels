# 训练权重的编码检查与迁移

训练控制台的“状态编码”和“动作编码”指定本次网络的目标布局。默认使用状态 v15 / 动作 v11（2054 / 448 维，54 种建筑完整编码）；也可选择状态 v14 / 动作 v9 或 v10（1790 / 256 维，旧建筑信息布局）。选项会限制有效组合。

选择服务器存档或上传权重后，控制台显示源版本、源维度、目标版本和恢复方式。点击“从权重读取参数”导入网络规模，保留当前目标编码和运行参数。启动时后端重新检查，不能绕过页面检查。

| 源编码 | 目标编码 | 自动处理 |
| --- | --- | --- |
| 与目标相同 | 与源相同 | 直接加载参数；同名优化器存档存在时恢复，并采用本次学习率 |
| v14 / v9 | v14 / v10 | 保留网络参数，清零新增动作输入权重，重新创建优化器 |
| v14 / v9 或 v10 | v15 / v11 | 按输入含义扩展参数，重新创建优化器 |
| 新编码 | 旧编码 | 拒绝降级 |

架构必须为 entity-v6，源与目标的 fast / balanced / large 网络规模必须一致；未知编码、维度不符或规模不一致会拒绝续训。

扩展至 v15 / v11 时，Transformer 主体及输出头保持原参数。全局、本人手牌和动作投影保留原输入列，新增列置零；城市嵌入保留旧建筑行，新增建筑行置零且可训练。状态头版本由 14 改为 15，对全局投影偏置补偿相应常数差异。源动作 v9 尚未使用的后缀也置零，避免随机参数影响升级后的决策。

迁移不修改源权重文件。之后保存的存档记录目标编码、目标维度及迁移来源。采样、MCTS、价值样本、训练张量、弱点对手和历史策略筛选均使用目标编码；历史策略池只接受完全相同的编码。旧规则样本和旧优化器状态不会带入编码升级。

参数迁移提供已有策略的起点；新增建筑效果仍需训练学习。它不替换仓库默认实战权重，也不会自动部署新权重。
