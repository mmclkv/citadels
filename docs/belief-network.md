# 分层信念网络 v2

入口：训练控制台 `training.html` → **信念网络训练**，或直接访问 `/belief-training.html`。

## 网络与编码

独立 `belief-v2-hierarchical` 模型，不修改策略网络的状态编码、动作编码或策略权重。v2 检查点与 v1 不兼容，需要重新训练。实体 Transformer 两层、四个注意力头，接单层历史 GRU；维度可选 64/128/192。历史默认保留最近 128 个可见事件，训练与推理采用相同窗口。

`python_backend/belief_encoding.py` 的 allow-list 观察构造器只编码当前玩家可见的信息。8 个相对座位，54 种建筑、27 种角色；建筑与角色完整注册表、输入维度和建筑数量界限都写入独立的编码契约。模型不读取其他人的手牌身份、未揭示角色、真实牌堆顺序、随机种子或私人日志。自己的手牌、选角时实际看到的角色池、法师依法看过的手牌可以编码。历史由可见局面变化构造，包含资源/手牌数量/城市变化、自己的手牌及角色、可见选角信息；不是完整规则日志编码。

输入为 `[8,143]` 玩家实体、`[124]` 全局特征、`[历史长度,237]` 可见事件，以及座位掩码、角色合法集合、未知角色槽位、手牌大小与目录剩余数量界限。实体含相对座位嵌入。角色解码每槽输出 27 个 logits；手牌解码每个玩家、每种建筑输出 0–5 张的 6 个 logits，并根据前序分配动态掩码。

网络显式分成两个概率分支：角色先验 `P(R|I)` 使用自回归分类，屏蔽已知或重复角色；同一玩家多个未知角色按 ID 排序，消除等价标签排列。手牌后验 `P(H|R,I)` 使用独立解码器，并把完整角色假设作为条件输入；手牌按建筑种类的数量自回归解码，维持精确手牌数和公开目录的数量界限。完整隐藏状态只在 `labels()` 中作为监督答案读取。女巫的执行角色与角色原始归属分开处理。

模型不会推断精确牌堆顺序、隐藏博物馆牌或私人真标记。它生成受约束的角色/手牌分配，不直接改写权威游戏状态。

## 训练

采样器各自启动独立 C++ 游戏进程，支持 2–8 人、角色组、随机混合/启发式/网络对手。冻结网络对手从默认权重及覆盖早期到近期的最多八个历史策略 checkpoint 中抽取，先检查架构及编码兼容性，用 CPU 直接策略推理，不重复运行 MCTS。策略训练和信念训练互斥；不会推进真实房间或更新策略网络。

在行动前，分别构造观察者输入和同一时刻的真实隐藏标签。只有完成的游戏才加入数据集，前期、中期、尾盘分层保留样本。整局划分训练/验证，固定种子对局的划分持久化到 `splits.json`，改变验证比例或重新运行不会把同一局重新分配到另一集合。

回放容量默认 64 局，一半近期、一半离开近期窗口后进入的蓄水池储备。自对弈数据以非 pickle 的压缩 NPZ 保存。训练最小化角色和手牌的条件负对数似然，分别按决策数量归一化，Adam 更新并裁剪梯度。页面显示训练损失和留出局的联合/角色/手牌 NLL；没有验证数据时显示空值，不虚报分数。

权重位于 `training-data/belief/checkpoints/`，包含独立契约、网络权重、Adam 状态、配置和指标；通过原子替换保存，使用 `allow_pickle=False` 加载。续训会检查网络维度和历史窗口。停止会等待采样器退出，并保存已经完成的训练更新。

## 实战接入

保存不会自动启用。页面选择 checkpoint 后按“启用选中权重”，或启动服务器时设置 `CITADELS_BELIEF_CHECKPOINT` 为文件路径。可随时“恢复原有采样”。运行时启用只影响当前服务器；若希望重启后继续启用，应配置环境变量。

普通决策先让原生采样器生成合法候选世界（默认 16 个，最多 128 个），并按隐藏角色分配分组。第一阶段估计每种角色假设的边际权重 `P(R|I) × E_q[P(H|R,I)/q(H|R)]`，用系统重采样先决定角色假设；第二阶段只在该角色组内按条件手牌权重 `P(H|R,I)/q(H|R)` 抽取世界。这样先分配有限粒子覆盖角色，再处理各角色下的手牌变化。角色和手牌分支都混入配置的均匀候选比例，避免模型过度集中。初始候选权重还会校正分层重采样概率，使它们能与搜索期间新提议的原生候选处在同一重要性权重尺度。

固定池重采样采用角色优先的两阶段抽样。实战默认启用的[逐步根世界采样](progressive-root-worlds.md)仍会在搜索中继续提议候选，并按 v2 的角色与条件手牌分支计算联合重要性权重；初始角色分层结果与后续提议共同进入 MCTS 根世界池。评分模型和真实观察在一次搜索内冻结。

在私人选牌、响应等含固定隐藏区域的阶段，第一版保留原采样，不对尚未支持的提议概率做不正确校正。固定池路径模型或数值出错时回退原采样，状态的 `beliefNetwork` 显示原因；动态路径初始评分失败时也回退原采样，后续补充评分失败则保留已有合法世界并停止补充，原因见 `mcts.particleSamplingError`。诊断包含采样耗时、候选数、有效样本数及独立粒子数。

候选重采样只是对学习到的联合信念的有限样本近似，不是对所有隐藏世界的穷举。候选数增加会增加耗时；NLL 改善也不保证夺冠率提高，启用前应固定策略权重、开局、人数及墙钟搜索预算进行对照评测。

## 接口与验证

- `GET /api/belief/status`：进度、配置、指标、存档列表和实战启用状态。
- `POST /api/belief/start`、`stop`、`activate`、`disable`：沿用原训练控制台的本机操作限制，配置上限 64 KB，存档文件限定在信念存档目录。
- 单元测试：`python -m unittest python_backend.test_belief python_backend.test_belief_api python_backend.test_neural_selection`。
- 设置 `CITADELS_BELIEF_GAME_ENGINE` 为已编译的 C++ 游戏引擎路径后，以上测试还会运行真实采集、训练、验证、续训与停止测试。
- 浏览器端到端测试：`node test/belief-training-e2e.js`，可设置 `PYTHON_PATH`、`PLAYWRIGHT_PATH`、`BROWSER_CHANNEL`，覆盖桌面与移动端训练、存档、启用和回退。

未随功能发布未经战力验证的默认信念权重；首次使用需先训练。
